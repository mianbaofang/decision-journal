# v0.10.0 - Identity unification: one name everywhere

发布日期：2026-11-13

## 中文

这一版解决的是"名字打架"：同一个产品 previously 同时叫 `choice-assistant`（安装名）、`Decision Brief`（产品名）、`decision-journal`（仓库名），搜索、安装、提 issue 时指向三个地方。v0.10.0 起全部统一为 **decision-journal（别纠结）**，功能与安全边界不变。

### 为什么改名

- 可安装 Skill、CLI、PyPI 项目、GitHub 仓库四个身份保持一致后，"搜得到、装得上、报得出 bug"指向同一个名字；
- `decision journal` 是真实存在搜索量的词，比自造名更可发现；
- 旧名 `choice-assistant` 描述的是"帮你选"，但产品真正的差异化是"记得住、可复盘"——日志才是本体。

### 变更

- Skill 目录：`skills/choice-assistant/` → `skills/decision-journal/`；SKILL.md `name` 同步。
- CLI：`scripts/choice_assistant.py` → `scripts/decision_journal.py`；安装后命令 `choice-assistant` → `decision-journal`。
- 环境变量：`CHOICE_*` → `DECISION_JOURNAL_*`（如 `DECISION_JOURNAL_LLM_API_KEY`）。
- 本地路径：`~/.choice/config.json` → `~/.decision-journal/config.json`；后端日志 `~/.decision-journal/backend.log`；SQLite `choice.db` → `decision_journal.db`，启动时自动迁移旧库（含 WAL，绝不覆盖新库已有数据）。
- CLI 新增 `--action stop`：只停本机 loopback 上、确认为本项目的后端进程；HTTP 错误改为可读提示。
- Web UI：首屏右侧新增真实 Demo 简报示例卡；侧栏最近决策显示时间与模式；移除加载期 `navigator.vibrate` 报错。
- 测试：桌面 UI 测试在后端未运行时自动拉起临时实例（独立临时数据库）；新增迁移四场景测试；evals 扩充到 8 正 6 负。
- 文档：README 快速开始给出一行安装（`npx skills add mianbaofang/decision-journal`）与装完第一句话；新增 `.claude-plugin/marketplace.json` 双通道。

### 迁移指南

- 装过旧版的用户：把 `~/.choice/config.json` 复制到 `~/.decision-journal/config.json`（或重新输入一次 Key）；后端启动时会自动把旧 `choice.db` 的决策与配置迁入新库，旧库改名为 `choice.db.migrated` 保留。
- 命令差异：`python scripts/choice_assistant.py` → `python scripts/decision_journal.py`；`CHOICE_LLM_API_KEY` → `DECISION_JOURNAL_LLM_API_KEY`，其余环境变量同理。

### 安装

```bash
npx skills add mianbaofang/decision-journal
```
